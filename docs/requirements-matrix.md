# API 商机雷达：需求依赖矩阵

版本：MVP 0.1.0　日期：2026-11-21

## 目标

把两件事放进同一个可复用 Skill：从公开信号形成少量、可审核的商机卡；从 Agent 使用记录中复盘用户本人的成长，并给出下一周可执行的商业改进。网站是这套工作流的可视化与导出入口，不冒充实时销售情报系统。

| 编号 | 需求 | 前置依赖 | MVP 实现 | 验收方式 |
|---|---|---|---|---|
| R1 | 雷达名称、方向、周期可自定义 | 无 | 配置弹窗；Skill `config.json` | 单测默认值、 trim 与数量边界；浏览器修改后刷新仍保留 |
| R2 | 公开信息转成少量商机卡 | R6 | 每张卡含公开信号、来源链接、商业假设、买方角色、下一动作 | 单测缺字段/非 HTTPS 来源会失败；网页能打开来源 |
| R3 | 商机必须人工审核 | R2 | “进入跟进 / 暂缓”状态，本地保存；归档等反信号可暂缓 | 单测状态流转；浏览器操作后计数与导出同步 |
| R4 | 复盘用户本人的成长 | R6 | 每条含学会了什么、项目、对话定位、证据、下一实验、商业关联 | 单测缺少证据或带原始聊天字段会失败；页面展示来源 |
| R5 | 产出可带走的 AI 化周报 | R1、R2、R3、R4 | 浏览器导出 Markdown；Skill CLI 生成 Markdown | 单测报告包含配置、商机、来源、成长和审核状态 |
| R6 | 公开与隐私边界 | 无 | 仅公开来源；成长只放抽象结论和定位，不放原始聊天、密钥、私人客户信息 | 数据校验；公开仓库扫描；页面固定“演示快照/假设待核验”标识 |
| R7 | 暖纸视觉与统一字体 | R1 | Noto Sans SC 正文；Maple Mono 数字与短元信息；细线、暖纸、森林绿 | 浏览器核字体加载；1440px 与 390px 截图检查 |
| R8 | 静态、离线、无构建链 | R1 | 单文件 HTML/CSS/JS + 本地字体；无后端与第三方运行依赖 | `file://` 打开可用；网络面板无外部请求；Node/Python 单测通过 |
| R9 | 公开仓库与成品网站 | R2—R8 全部通过 | GitHub 公开仓库 + GitHub Pages | 核仓库文件、提交、线上 HTTP 与桌面/手机页面 |

## 依赖顺序

1. 先锁定 R6 的数据边界，再实现 R1/R2/R4 的数据结构。
2. 先写失败测试，再实现核心校验、状态流转与报告生成。
3. R3/R5 复用同一份状态，避免网页显示与导出结果不一致。
4. R7/R8 做浏览器实测，不只审 CSS。
5. R9 最后发布；发布后再次核验线上版本。

## MVP 明确不做

- 不做全网爬虫、自动登录、自动发邮件或自动触达。
- 不把公开技术信号直接写成“客户有采购意向”。
- 不生成虚构联系人、预算、成交概率或商业结果。
- 不做多用户、账户系统、数据库、定时调度和后台服务。
- 不在公开仓库保存原始对话、客户隐私、密钥或个人日志全文。

## 迭代切片

- **迭代 1：可计算。** Node 与 Python 测试先行，跑通配置、校验、审核、Markdown 与静态站点导出。
- **迭代 2：可使用。** 完成商机审核、成长新增、自定义配置、本地保存、Markdown 下载。
- **迭代 3：可公开。** 实际检查桌面/手机与离线资源，发布 GitHub/Pages，并核线上版本。
