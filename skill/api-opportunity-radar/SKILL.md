# API 商机雷达

把两条证据链放进同一份周报：

1. **公开信号 → 商机卡 → 人工审核 → 下一动作。**
2. **Agent 使用记录 → 用户本人成长 → 商业关联 → 下一实验。**

网站只是展示与导出入口；工作区 JSON 才是可持续交接的事实源。不要把长对话当作唯一数据库。

## 首次配置

1. 若用户没有指定方向，默认使用 `AI API / 海外 AI 应用与自动化团队`，但允许改成任意行业；雷达名称也可只叫“商机雷达”。
2. 在工作目录运行：

```bash
python scripts/radar.py init --root opportunity-workspace
```

3. 编辑 `opportunity-workspace/config.json`，确认名称、关注方向、周期和每周最大卡数。默认上限 5，硬上限 10。
4. 已有工作区时不要重新 `init`，避免覆盖。先读取现有 JSON 与上周报告。

## 每周工作流

### A. 采集公开信号

- 优先读取 `browser-use-automation` Skill，通过浏览器采集公开网页；需要跨源检索时可用公共搜索。
- 只记录公开可复核信息：官方仓库、官方文档、公开 issue、招聘页、产品更新、公开访谈。
- 每条事实保留来源标题、URL、采集日期和原文依据。来源打不开就标“未核验”，不要补写。
- 技术热度不等于采购意向。归档、停止维护、许可证冲突等反信号也要保留，可生成“暂缓”卡。

### B. 形成少量商机卡

每个候选项先回答四个问题：

1. 公开事实是什么？
2. 由此产生的商业假设是什么，怎样可以被证伪？
3. 应该找哪类角色验证，而不是声称谁一定会买？
4. 下一步最小动作是什么，能否在一周内完成？

按 `references/schema.md` 写入 `opportunities.json`。只保留 `maxCards` 张以内；默认状态为 `pending`，由用户审核后改成 `follow` 或 `hold`。

禁止虚构联系人、预算、采购阶段、成交概率、合同金额或商业结果。未经用户明确授权，不发送邮件、不私信、不自动触达。

### C. 复盘用户本人的成长

只使用用户明确提供或授权的 Agent 使用记录、项目文件、导出对话和成长日志。公开网页采集与私人使用记录必须分开处理。

每条成长必须同时包含：

- **学会了什么**：写能力变化，不写“调用了很多工具”。
- **来源项目与对话定位**：项目名 + 日期时间/对话主题即可；公开产物不放私密会话 ID。
- **证据与结论边界**：发生了什么前后变化；哪些结论不能推出。
- **商业关联**：这项变化怎样改善来源筛选、需求访谈、验证样例、交付或回款动作。
- **下一实验**：下一周可观察、可复核的一步。

优先寻找“以前怎么做 → 现在怎么做”的对照。没有证据时写“本周未形成成长结论”，不要编造。原始聊天只留在用户授权的私密位置，公开 JSON 禁止 `rawTranscript` 字段。

### D. 校验与生成

```bash
python scripts/radar.py validate --root opportunity-workspace
python scripts/radar.py report --root opportunity-workspace --output opportunity-workspace/weekly.md
python scripts/radar.py site --root opportunity-workspace --output opportunity-workspace/site
```

- `validate` 失败时先修数据，不绕过校验。
- `report` 生成含来源、审核状态、成长证据的 Markdown。
- `site` 生成自包含静态网站；字体随站点复制，无外部运行依赖。
- 新会话接手时，先读工作区 JSON 和最近周报，再复述本周目标、未决假设与下一步。

## 输出要求

最终给用户：本周商机卡数量与状态、2—3 条最重要的成长、一个最优先商业实验、周报文件和可访问网站。另列“未证实/暂缓”项，避免只展示正向结论。

## 公开分享前检查

- 所有来源为 HTTPS，商业假设仍明确标“待人工验证”。
- 删除原始对话、私人客户名、未公开金额、密钥、令牌与个人身份信息。
- 成长条目只保留脱敏摘要和定位，不公开整本日志。
- 测试脚本通过；390px 手机无横向滚动；导出内容与页面状态一致。
